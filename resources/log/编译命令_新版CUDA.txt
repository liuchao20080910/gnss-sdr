GNSS-SDR 编译命令（上游 v0.0.22 起：CUDA 12.6 + Jetson Orin NX）
本文件是新增说明；resources/log/编译命令.txt 为旧版，保持原样未改动。
================================================================================

一、环境
  Jetson Orin NX (aarch64, compute capability 8.7)
  Ubuntu 22.04.5 / GCC 11.4 / CMake 3.22.1 / CUDA 12.6 (/usr/local/cuda-12.6)

二、推荐编译命令（不改任何源码）
  cd gnss-sdr
  mkdir build && cd build
  cmake .. -DENABLE_CUDA=ON \
           -DCMAKE_CXX_FLAGS="-I/usr/local/cuda-12.6/include" \
           -DCMAKE_CUDA_ARCHITECTURES=87
  make -j4
  sudo make install

  为什么多了这两个参数：

  1) -DCMAKE_CXX_FLAGS 里的 CUDA include 目录，是绕上游 v0.0.22 的一个构建 bug。
     tracking/gnuradio_blocks、tracking/adapters、tracking/libs、acquisition/libs、
     core/receiver、src/main 这 6 处 CMakeLists 用的是
     ${CMAKE_CUDA_TOOLKIT_INCLUDE_DIRECTORIES}（旧 FindCUDA 变量），
     而上游改成 find_package(CUDAToolkit) 之后该变量在这些子目录里为空，
     于是编译 gps_l1_ca_dll_pll_tracking_gpu_cc.cc 时直接报
       cuda_multicorrelator.h:34:10: fatal error: cuda.h: No such file or directory
     报错详情与修复建议见 ~/gnss-sdr-upstream-issue-cuda-include.md（本地文档）。

  2) -DCMAKE_CUDA_ARCHITECTURES=87 对应 Orin NX（sm_87）。
     不指定时会沿用 build/CMakeCache.txt 里的旧值（旧值可能是 52），
     靠 PTX JIT 也能跑，但没有原生 SASS，首次启动还要 JIT。

  3) 注意：改 CMAKE_CUDA_ARCHITECTURES 不会触发 .cu 重编（CMake 不跟踪编译标志
     变化）。要确认真的按 87 编了，得强制重编 CUDA 目标：
       find build -name '*.cu.o' -delete
       cd build && make -j4
     验证方法：grep -r 'arch=compute_87' build/src/algorithms/*/libs/CMakeFiles/

三、关于"用补丁代替 -DCMAKE_CXX_FLAGS"
  已尝试在顶层 CMakeLists.txt 里提前 find_package(CUDAToolkit) 并 include_directories()，
  但 tracking_gr_blocks 的编译仍未拿到该 include（上游变量作用域问题）。
  因此目前以 -DCMAKE_CXX_FLAGS="-I/usr/local/cuda-12.6/include" 为准，
  这是实测唯一有效的方式。补丁草案留在 ~/gnss-sdr-local-cuda-include.patch，
  问题描述与上游修复建议见 ~/gnss-sdr-upstream-issue-cuda-include.md。

四、运行
  cd ~/Workspace/GNSS/gnss-sdr
  ./gnss-sdr/build/src/main/gnss-sdr \
      --config_file=./gnss-sdr/resources/config/gnss-sdr_GPS_L1C_GPU.conf \
      --log_dir=./logs --carrier_lock_th=0.5 --max_lock_fail=200

五、调试打印开关（默认关闭，编译期消除）
  源码中带 GNSS_SDR_VERBOSE_DEBUG 宏控制的诊断打印，默认 #define 为 0。
  涉及文件：
    src/algorithms/tracking/gnuradio_blocks/dll_pll_veml_tracking.cc
    src/algorithms/tracking/gnuradio_blocks/gps_l1_ca_dll_pll_tracking_gpu_cc.cc
    src/algorithms/tracking/libs/tracking_2nd_DLL_filter.cc
    src/algorithms/observables/gnuradio_blocks/hybrid_observables_gs.cc
  需要时把对应文件里的 #define GNSS_SDR_VERBOSE_DEBUG 0 改成 1 重新编译即可。

六、本机实测（2026-11-07，Orin NX，60 s 数据）
  总耗时约 123 s（26 Msps，20 通道，GPU 跟踪），约为实时的 0.49 倍；
  首次定位约 64 s（等导航电文 30 s 一帧 + 捕获）。
  定位结果与 CPU 版一致（<2 m），详见 resources/log/GPU_CPU定位测试log.txt。
